# Authentication

## CRM API v2 조회·쓰기 권한

API는 토큰 소유자의 **현재 역할 권한**을 요청마다 확인합니다. 인증된 토큰이 있어도 해당 모듈의 권한이 없거나 권한 범위가 `None`이면 `403 Forbidden`을 반환합니다.

- 조회에는 해당 모듈의 조회 권한이 필요합니다. `POST` 방식의 검색·통계 조회도 조회 권한을 확인합니다.
- 생성·수정·삭제에는 해당 모듈의 수정 권한이 필요합니다. 읽기 전용 사용자는 역할에 수정 권한이 있어도 데이터를 변경할 수 없으며, 저장 전에 `403 Forbidden`으로 거부됩니다. 조회 권한이 있으면 조회 요청은 사용할 수 있습니다.
- `All` / `Team` / `Own`은 권한 보유 여부 판단에 사용하며, 이 범위에 따른 개별 레코드 제한은 적용하지 않습니다. 앱 화면에서 볼 수 있는 레코드 범위와 동일하다고 가정하지 마세요.
- 고객·회사는 연락처 권한, 필드 정의는 필드 관리 권한을 사용합니다. 커스텀 오브젝트는 종류별 조회·수정 권한을 확인합니다.
- 생성·수정 요청에 노트 생성을 포함하면 노트 수정 권한도 필요합니다. 딜·리드 연결은 두 모듈의 수정 권한을 모두 확인합니다. 메인 견적서로 생성하는 요청은 견적서와 연결 딜 또는 리드의 수정 권한이 필요합니다.
- 딜·리드의 견적서 조회는 해당 딜·리드와 견적서의 조회 권한이 모두 필요합니다. 모두싸인 문서의 딜 조회는 모두싸인과 딜의 조회 권한을 모두 확인합니다. 연결 데이터 조회는 출발·대상 모듈의 조회 권한을 확인합니다.
- 커스텀 오브젝트 전체 데이터·이력·액티비티 목록 및 종류 목록은 조회 권한이 있는 종류만 반환합니다. 조회 가능한 종류가 하나도 없거나, 권한 없는 종류·레코드를 직접 지정하면 `403 Forbidden`을 반환합니다. 커스텀 오브젝트 연결 목록에도 조회 가능한 종류 제한이 적용됩니다.
- 역할 권한 변경은 같은 토큰의 다음 요청부터 반영됩니다. 쓰기 요청은 `Idempotency-Key`가 있어도 현재 권한을 먼저 확인합니다.

CRM 토큰으로 SDR 프로필을 생성·조회하는 `/v2/sdr`, `/v2/sdr/{onboardingId}`와 별도 프로필 키를 사용하는 SeA API는 위 정책의 적용 대상이 아닙니다. 이 정책을 v1·v3 API로 확대 적용하지 않습니다.

권한이 부족하면 토큰 소유자의 역할과 좌석 유형, 요청이 사용하는 각 모듈의 조회·수정 권한을 확인해 주세요.
